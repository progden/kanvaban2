# 與專家協作的提問規則 — 本體論分析

> 目的：把 AI 與系統分析專家協作時的 10 種常見失誤，收斂成可檢查的實體、關係與不變量。
> 適用位置：`.dev/prompts/`（提問規則）、`checks.md`（可腳本化的項目）。

## 1. 實體（主體）

| 實體 | 定義 | 關鍵屬性 |
|---|---|---|
| 斷言 Assertion | 出現在 AI 輸出裡的任何一句「是什麼」 | 來源類型：`spec原文` / `推論` / `假設` / `專家原話`；位置（檔名、UC 編號） |
| 提問 Question | AI 向專家提出的問題 | 引用的斷言集合；Level（模組 / feature / UC / scenario） |
| 選項 Option | 提問中可供選擇的項目 | 所屬類別（角色、狀態、模組、事件…） |
| 類別總表 Registry | 某類別的完整既有項目表 | 項目集合 |
| 決策 Decision | 專家定案 | 原話；所解決的提問；所覆蓋的斷言 |
| 輸入片段 Fragment | 專家非循序給的一句話 | 暫歸模組；狀態 `待確認` / `已確認` |

## 2. 關係

| 關係 | 主詞 → 受詞 | 數量約束 |
|---|---|---|
| `derived_from` | 推論 → 斷言 | ≥ 1；受詞只能是 `spec原文` 或 `決策` |
| `fills` | 假設 → 缺口 | 1 |
| `affects` | 假設 → UC | ≥ 1，必須列出 |
| `cites` | 提問 → 斷言 | ≥ 1 |
| `offers` | 提問 → 選項 | 0..n |
| `belongs_to` | 選項 → 類別總表 | 0..1 |
| `resolves` | 決策 → 提問 | 1 |
| `supersedes` | 決策 → 斷言 | 0..n；> 0 時必開 CR |
| `assigned_to` | 片段 → 模組 | 1；狀態 `待確認` 直到有決策 |

## 3. 依主體分類的 10 種情況與不變量

### 主體 A：斷言（來源標記）

| 編號 | 不變量 | 對應情況 |
|---|---|---|
| A1 | 每個斷言必有來源類型，同一句不可混兩種 | 1. 問題裡分不清 spec 原話還是 AI 推論 |
| A2 | `假設` 不得進 spec 正文，只能進待確認清單，且必附 `affects` 的 UC 清單 | 4. AI 用「常見做法」填缺口，寫得像定案 |
| A3 | `專家原話` 回寫時不可變成 `推論`；擴充解釋即違規 | 5. 專家簡短回答，AI 擅自擴充 |

### 主體 B：選項 × 類別總表

| 編號 | 不變量 | 對應情況 |
|---|---|---|
| B1 | 提問 `offers` 的選項若 `belongs_to` 某類別，該類別總表必須完整呈現，並含「其他既有項目」 | 2. 給二選一，但更好的答案在既有選項裡 |
| B2 | 提案新選項（新模組、拆分）前，必須先查總表與決策記錄是否已有相同或已否決項目 | 6. AI 提議拆模組，但專家早已評估過 |

### 主體 C：決策（定案、矛盾、覆蓋）

| 編號 | 不變量 | 對應情況 |
|---|---|---|
| C1 | 兩個 `spec原文` 斷言互斥時，提問必須並列引用兩者；選項固定三條：保留 A / 保留 B / 缺區分條件 | 3. 兩條 spec 互相矛盾 |
| C2 | 提問不得 `cites` 已被決策 `resolves` 的問題；若重開需明示「推翻先前定案」 | 8. 重複問已定案的事 |
| C3 | 決策 `supersedes` 既有斷言時，必須顯示「原文 → 新文」並開 CR，不得靜默改寫 | 9. 新回答覆蓋舊 spec，AI 默默改掉 |

### 主體 D：輸入片段（歸屬）

| 編號 | 不變量 | 對應情況 |
|---|---|---|
| D1 | 片段 `assigned_to` 模組前狀態必為 `待確認`，保留原話與歸類理由；批次確認，不逐句打斷 | 7. 非循序輸入被硬歸入某模組 |

### 主體 E：提問本身（Level 與判斷權）

| 編號 | 不變量 | 對應情況 |
|---|---|---|
| E1 | 提問只呈現事實屬性（影響範圍、衝突的 pre/post condition、UC 數量），不含評價語 | 10. AI 用說服語氣「建議這樣比較好」 |
| E2 | 提問必標 Level，避免專家回答落錯層 | （顆粒度錯置） |

## 4. 提問輸出格式（由 A1、B1、C1、E2 推得）

```
[Level] 模組 / feature / UC / scenario
[引用]
  spec原文：<檔名 §UC-xxx>「…逐字…」
  推論：由上述原文推得 …（若有）
  假設：…（若有，附 affects UC 清單）
[問題] …
[選項]（若屬某類別）
  類別總表：<完整表格>
  候選：A、B
  其他既有項目 / 以上皆非
[事實] 影響 UC 數 / 衝突的 pre-post condition
```

## 5. 可檢查性

| 主體 | 檢查方式 | 檢查點 |
|---|---|---|
| A | 腳本 | 每個斷言是否有來源標記；`假設` 是否出現在正文 |
| B | 腳本 | 提問含選項時，是否貼出對應類別總表 |
| C | 腳本 | 提問引用的項目是否已在決策記錄中；`supersedes` 是否對應 CR |
| D | 提示詞 | 片段狀態流轉 |
| E | 提示詞 | 語氣與 Level 標記 |

## 6. 根因

10 種情況只有兩個根因：

1. **斷言缺來源**（主體 A）— C 的三條是 A 在「決策」這個特殊斷言上的延伸。
2. **選項空間被截斷**（主體 B）。
