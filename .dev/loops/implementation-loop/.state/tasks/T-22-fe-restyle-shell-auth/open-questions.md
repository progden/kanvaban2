`Login.dc.html` 品牌欄下方標註：『⚠️ 規格未定義：登入頁的品牌敘述、產品名稱與插圖，`ui-user-membership.md` 未定義』（該畫面同時畫出產品名稱占位字『[產品名稱]』、標語『把看板放到一張畫不完的桌子上。』與看板示意插圖）。

`Signup.dc.html` 品牌欄下方標註：『⚠️ 規格未定義：此說明卡的文案與版面，`ui-user-membership.md` 未定義』（該畫面同時畫出說明卡標題『帳號建立後無法刪除』與清單項目）。

`ui-user-membership.md` 的 `s-login`／`s-signup` 兩節「資料」「操作」「驗收條件」表中，都沒有出現「產品名稱」「品牌標語」「插圖」「說明卡」這幾個詞或對應欄位；`s-login`「待確認事項」欄寫的是『（無）』。

推論：這兩處設計稿的 `.warn` 註記本身就是設計稿作者對「這段文案／版面沒有 spec 依據」的自我標註，`ui-user-membership.md` 目前定案內容也確實沒有定義這些文字與插圖，屬於規格未定義、需要人工決定是否上產品，而不是 Dev 可以逕行認定「已有依據」的內容。

問題：TopBar／s-login／s-signup 顯示的產品名稱占位字『[產品名稱]』、s-login 的品牌標語與看板示意插圖、s-signup 說明卡（標題『帳號建立後無法刪除』與其清單文案），要不要保留在畫面上、要保留哪一版文案？

選項：A. 維持現狀（占位字／目前文案／插圖照設計稿做，等有正式產品名稱與文案再換）；B. 先把占位字與尚無依據的文案拿掉，只保留有 spec 依據的欄位與按鈕，等文案定案後再補；C. 現在就請人工訂出正式產品名稱與文案，寫進 `ui-user-membership.md` 並走 CR 補上依據。

（本輪已依 Review 指示，把 s-signup 說明卡中「帳號 ID 全系統唯一，之後不能改」這句改成欄位表原文『非空、全系統不可重複』對應的『帳號 ID 全系統不可重複』，移除沒有 spec 依據的「之後不能改」宣稱；其餘占位文案與插圖維持顯示，等待本則 OQ 決定。）
